# Contributing to GUTTR

GUTTR is a creator-led comic survey platform. We invite meaningful contributions to its **asset ecosystem, research methods, accessibility, and documentation**, without making the proprietary application code available in this public repository.

## Ways to participate

| Interested in | How to contribute |
| --- | --- |
| Comic art | Propose an original, reusable [comic kit](docs/contribute-a-kit.md) |
| Research | Share a survey-use case, test scenario, or study-methodology suggestion |
| Usability | Report confusing steps in Studio, Experiment Room, or respondent view |
| Accessibility | Describe barriers affecting keyboard users, visual reading order, or alternative answer modalities |
| Documentation | Propose improvements to public guidance or technique examples |
| Feature ideas | Describe the need, audience, constraints, and smallest useful solution |

Use the [GitHub Issues](https://github.com/shriy-singh/guttr/issues) templates to start. If an issue concerns private user data or a security vulnerability, **do not publish the details in a public issue**.

## Comic kits and licensing

- Creators retain ownership of their original artwork unless a separate agreement says otherwise.
- A proposal is not a transfer of intellectual property or an automatic license.
- Asset submissions require clear provenance, license/permission information, and attribution.
- Permission to embed artwork in a survey is different from permission to redistribute source files.
- Artist compensation or commissioning terms are not finalized. Do not assume payment or a revenue share.
- Do not upload art you scraped, copied, or otherwise lack rights to redistribute.

See [Contribute a comic kit](docs/contribute-a-kit.md) and [Asset rights](docs/asset-rights.md).

## Public repository scope

This repository intentionally contains public product information and collaboration workflows. **The complete application source, databases, private services, keys, and restricted third-party artwork are not included.**

We welcome reports and ideas, but we are not inviting public pull requests that recreate the proprietary survey platform from scratch. Code implementation proposals can be discussed before any private collaboration is considered.

## Suggestions we can evaluate

When proposing a change, explain:

1. Who would benefit and what problem they have.
2. The present behavior and desired improvement.
3. How someone could verify that the improvement worked.
4. Accessibility, data handling, or copyright considerations.

Maintainers retain discretion over whether and when ideas are implemented. Public issue discussions should not include passwords, identifying respondent records, or unpublished research data.

## Security

For security concerns, do not post exploit details in public issues. Contact the project maintainer privately using an established contact method, then coordinate disclosure.
